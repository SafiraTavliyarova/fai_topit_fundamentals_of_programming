В текущей реализации ветвь `case _:` (для неизвестного типа работы) **недостижима**, потому что некорректный тип работы отлавливается на этапе проверки диапазонов в Части 1. **Зачем она нужна:** Эта ветвь добавлена для надёжности и расширяемости кода. Если в будущем логика проверки изменится (например, разрешатся новые типы работ), эта ветвь защитит от непредвиденных значений.

## Задание 2. 

### Описание решения

Программа обрабатывает список измерений `measurements = [12, 15, 11, 18, 18, 9, 21, 15, 7, 18]` и выполняет набор базовых алгоритмов: вычисление суммы, поиск минимума и максимума, подсчёт чётных значений, подсчёт значений выше среднего и линейный поиск. Все алгоритмы реализованы вручную без использования встроенных функций `min()`, `max()`, `sum()` и `list.count()`. Решение разделено на три логических этапа.

### Ключевые моменты реализации

**Этап 1. Один проход по списку**  
За один цикл `for` одновременно вычисляются четыре характеристики:
- **Сумма** — накопление через `total += value`
- **Минимум** — инициализация первым элементом, обновление при `value < mn`
- **Максимум** — инициализация первым элементом, обновление при `value > mx`
- **Количество чётных** — проверка `value % 2 == 0`

Такой подход эффективен: список проходится один раз, а не четыре.

**Этап 2. Второй проход — подсчёт значений выше среднего**  
Среднее арифметическое вычисляется **после** первого цикла как `average = total / n`, поскольку сумма становится известна только после обработки всех элементов. Поэтому подсчёт значений, превосходящих среднее, требует отдельного прохода.

**Этап 3. Линейный поиск первого вхождения**  
Пользователь вводит число, программа ищет его первое вхождение в списке. Переменная `found_index` инициализируется значением `-1` (сигнал «не найдено»). При первом совпадении цикл прерывается через `break` — это гарантирует, что будет найден именно **первый** индекс, даже если число встречается несколько раз.

### Анализ сложности реализованных алгоритмов

#### 1. Вычисление суммы, минимума, максимума и количества чётных

- **Временная сложность: O(n)**, где n — длина списка `measurements`.
- **От какого параметра зависит число операций:** от количества элементов в списке. Каждый элемент обрабатывается ровно один раз.
- **Пространственная сложность: O(1).** Используется фиксированное количество переменных (`total`, `mn`, `mx`, `count_chet`).

#### 2. Подсчёт значений выше среднего

- **Временная сложность: O(n).** Второй проход по списку, для каждого элемента выполняется одно сравнение.
- **Пространственная сложность: O(1).** Одна дополнительная переменная-счётчик.

#### 3. Линейный поиск первого вхождения

- **Временная сложность: O(n) в худшем случае, O(1) в лучшем.**
  - Худший случай: искомого числа нет в списке — проверяются все n элементов.
  - Лучший случай: число находится на первой позиции — одна проверка.
- **Пространственная сложность: O(1).** Одна переменная `found_index`.

### Тестовые сценарии

| measurements = [12, 15, 11, 18, 18, 9, 21, 15, 7, 18] | Сумма: 144, Мин: 7, Макс: 21, Чётных: 4, Среднее: 14.4 | Совпадает |
| Поиск числа 18 | Индекс: 3 (первое вхождение) | 3 |
| Поиск числа 99 | Индекс: -1 (не найдено) | -1 |
| Поиск числа 12 | Индекс: 0 (первый элемент) | 0 |


От какого параметра зависит число операций: от n — длины массива.

Почему ограничение делителей корнем (это из основной части) — если n = a·b и a ≤ b, то a ≤ √n, значит любой составной n имеет делитель ≤ √n.

Почему бинарный поиск требует сортировки: свойство «слева меньше, справа больше» — только оно позволяет отбрасывать половину.

### Вывод

1. Для повторяющихся проходов (сумма, минимум, максимум, счётчики) достаточно одного прохода O(n); среднее требует двух проходов, так как зависит от суммы.
2. Линейный поиск прост, но плохо масштабируется; бинарный резко выигрывает на больших n, но требует отсортированных данных.
3. Проверка простоты за O(√n) вместо O(n) — пример того, как математическое наблюдение уменьшает число операций.

## Задание 3

### Описание решения

Программа хранит результаты студентов в нескольких структурах данных и отвечает на текстовые запросы. Для каждой операции выбрана оптимальная коллекция.

### Что делает `setdefault`

```python
attempts.setdefault(name, [])
```
Этот метод делает две вещи сразу:
Если ключа нет — создаёт его со значением по умолчанию ([]) и возвращает это значение.
Если ключ уже есть — ничего не меняет и возвращает текущее значение.
setdefault не перезаписывает список, а возвращает существующий. Если бы setdefault всегда перезаписывал — мы бы теряли старые оценки.

Что делает get
```python
counts.get(key, 0)
```
Этот метод:
Если ключ есть — возвращает его значение;
Если ключа нет — возвращает значение по умолчанию (второй аргумент), не создавая ключ.

Разница setdefault и get: setdefault создаёт ключ, даже если он тут же перезаписывается. get ключ не создаёт — он только читает. Для счётчика get чище: «прочитать или 0, прибавить, записать».
Объяснение выбора структур данных
1. Почему множество (set) подходит для хранения уникальных значений?
Множество по своей природе хранит только уникальные элементы. Если мы попытаемся добавить "anna" второй раз, множество просто проигнорирует повтор. Проверка «а есть ли уже такой элемент?» занимает в среднем O(1).
2. Почему кортеж (tuple) можно использовать как ключ словаря?
Ключом словаря может быть только хешируемый (неизменяемый) объект. Кортеж — неизменяемая последовательность, поэтому для него можно вычислить хеш, и он не изменится со временем.
3. Почему список (list) нельзя использовать как ключ словаря?
Список — изменяемая структура. Если бы список был ключом, то после его изменения хеш тоже изменился бы, и словарь не смог бы найти этот ключ. Python запрещает это и выдаёт TypeError: unhashable type: 'list'.
4. Почему словарь предпочтительнее списка для частого поиска по составному ключу?
Если бы мы хранили результаты в виде списка кортежей, поиск занял бы O(n). Словарь использует хеш-таблицу — поиск по ключу происходит за O(1), независимо от размера данных.
Вывод
Выбор структуры данных критически влияет на эффективность программы. Множество гарантирует уникальность, кортеж позволяет использовать составные ключи, а словарь обеспечивает мгновенный поиск. Методы setdefault и get упрощают работу со словарями, избегая лишних проверок.

## Задание 4. Функции, параметры и области видимости

В этом задании я исследовала механизмы работы функций в Python: позиционные и именованные параметры, значения по умолчанию, области видимости (LEGB), замыкания и функции высшего порядка.

### Позиционные и именованные аргументы

**Позиционные аргументы** передаются по порядку:
```python
def make_tea(size, sugar, milk):
    print(f"Чай {size}, сахар {sugar}, молоко {milk}")

make_tea("большой", 2, True)  # size="большой", sugar=2, milk=True
```

Именованные аргументы передаются с указанием имени — порядок не важен:
``` python
make_tea(milk=True, size="большой", sugar=2)
```

Звёздочка * и значения по умолчанию

Звёздочка * в параметрах означает: «Всё, что стоит после меня, передавай только именованно»:

``` python
def build_report(student, results, *, precision=1):
    # precision можно передать только как build_report("Анна", [5, 4], precision=2)
```

Схема
```text
[ Встроенная область (B) ]  <-- len(), print(), max() и др.
           ^
           |
[ Глобальная область (G) ]  <-- course = "Python для начинающих"
           ^
           |
[ Объемлющая (E) ]          <-- teacher, student_count (внутри outer_function)
           ^
           |
[ Локальная (L) ]           <-- измененная student_count (внутри inner_function)
```

Как работают проверки через assert

assert — это способ сказать программе: «Я утверждаю, что это правда. Если нет — остановись и покажи ошибку».
```python
assert условие
assert условие, "Текст ошибки, если условие ложно"
```
Используется для быстрого тестирования функций прямо в коде.

### Исследование LEGB (Области видимости)

Что такое nonlocal?

Это ключевое слово позволяет вложенной функции изменять переменную из объемлющей (внешней) функции. Без него Python создал бы новую локальную переменную.

Порядок поиска имён (LEGB):

Local (L) — локальные переменные функции

Enclosing (E) — переменные внешней (обёрточной) функции

Global (G) — глобальные переменные

Built-in (B) — встроенные функции (print, len и т.д.)

Глобальная переменная course осталась неизменной, так как мы не использовали ключевое слово global.
Ошибка изменяемого значения по умолчанию
Почему так происходит?
В Python значения по умолчанию вычисляются один раз при определении функции. Если это изменяемый объект (список, словарь), он будет общим для всех вызовов.

Исправление: использовать None как значение по умолчанию и создавать новый объект внутри функции:

```python
def add_result(value, results=None):
    if results is None:
        results = []
    results.append(value)
    return results
```
Функции высшего порядка и замыкания
Функция высшего порядка — функция, которая принимает другую функцию как аргумент или возвращает функцию.

apply_to_results(operation, values) — принимает функцию operation и применяет её к каждому элементу списка values. Можно передавать встроенные функции (abs) или lambda:
```python
lambda x: x + 5  # анонимная функция, которая берёт x и возвращает x + 5
```

make_threshold_checker(threshold) — фабрика функций. Возвращает вложенную функцию checker, которая «запоминает» значение threshold через механизм замыкания.
Замыкание (Closure) — когда внутренняя функция использует переменную из внешней функции, и эта переменная сохраняется в памяти даже после завершения внешней функции.
Выводы
1. Параметры функций: позиционные передаются по порядку, именованные — по имени.
2. LEGB: Python ищет имена по правилу Local → Enclosing → Global → Built-in. nonlocal позволяет изменять переменные из внешней области.
3. Изменяемые значения по умолчанию: инициализируются один раз. Используйте None и создавайте объект внутри функции.
4. Замыкания: функции «запоминают» переменные из внешней области. Фабрики функций позволяют создавать множество проверок с разными параметрами без дублирования кода.

Практическое расширение

Схема фабрики
```text
make_threshold_checker(75)
         │
         ├── threshold = 75  (запоминается!)
         │
         └── возвращает функцию checker, которая:
                  │
                  └── при вызове checker(80):
                         │
                         └── 80 >= 75 → True 


make_threshold_checker(90)
         │
         ├── threshold = 90  (запоминается!)
         │
         └── возвращает функцию checker, которая:
                  │
                  └── при вызове checker(80):
                         │
                         └── 80 >= 90 → False 
            
```


## Задание 5. Анализатор учебных результатов
Схема
``` text
main()
├── student_summary() — статистика одного студента
│   ├── mean() — среднее
│   ├── minimum() — минимум
│   ├── maximum() — максимум
│   └── classify() — категория
├── group_summary() — статистика всей группы
├── find_top_students() — поиск лидеров
└── format_report() — форматирование отчёта

```

### Описание решения

Программа анализирует результаты группы студентов: вычисляет индивидуальные и групповые статистики, определяет категории результатов, находит лидеров и формирует текстовый отчёт. Решение построено по принципу декомпозиции — каждая функция выполняет одну конкретную задачу.

### Контракты функций

**`mean(values: list) -> float`**
- **Вход:** список чисел (`int` или `float`)
- **Выход:** среднее арифметическое (`float`) или `None`, если список пустой
- **Особые случаи:** пустой список → `None` (избегает деления на ноль)

**`minimum(values: list) -> float`**
- **Вход:** список чисел
- **Выход:** минимальное значение или `None`, если список пустой

**`maximum(values: list) -> float`**
- **Вход:** список чисел
- **Выход:** максимальное значение или `None`, если список пустой

**`classify(score: float) -> str`**
- **Вход:** числовой результат от 0 до 100 (или `None`)
- **Выход:** строка с категорией (`'отличный'`, `'хороший'`, `'удовлетворительный'`, `'недостаточный'`, `'нет данных'`, `'некорректный'`)
- **Особые случаи:** `None` → `'нет данных'`; значение вне [0, 100] → `'некорректный'`

**`student_summary(name: str, results: list) -> dict`**
- **Вход:** имя студента, список результатов
- **Выход:** словарь с ключами `name`, `mean`, `min`, `max`, `category`
- **Особые случаи:** пустой список → поля `mean`, `min`, `max` равны `None`, категория `'нет данных'`

**`group_summary(students: dict) -> dict`**
- **Вход:** словарь `{имя: [результаты]}`
- **Выход:** словарь с ключами `total_students`, `category_counts`, `group_mean`
- **Особые случаи:** пустой словарь → `group_mean = None`; студенты без результатов учитываются в категории `'нет данных'`, но не влияют на `group_mean`

**`find_top_students(students: dict) -> list`**
- **Вход:** словарь `{имя: [результаты]}`
- **Выход:** список имён студентов с наибольшим средним баллом
- **Особые случаи:** пустой словарь → пустой список `[]`; при одинаковом среднем балле возвращает всех лидеров

**`format_report(student_data: list, group_data: dict) -> str`**
- **Вход:** список словарей со статистикой студентов, словарь со статистикой группы
- **Выход:** строка с текстовым отчётом
- **Особые случаи:** корректно обрабатывает `None` в полях `mean` и `group_mean`

### Декомпозиция программы

Программа разбита на три уровня:

**1. Базовые функции (работа со списками):**
- `mean()`, `minimum()`, `maximum()` — примитивные операции над числовыми списками
- `classify()` — преобразование числа в категорию

**2. Функции агрегации (работа со студентами и группой):**
- `student_summary()` — использует базовые функции для одного студента
- `group_summary()` — использует `mean()` и `classify()` для всей группы
- `find_top_students()` — использует `mean()` и `maximum()` для поиска лидеров

**3. Функция представления:**
- `format_report()` — преобразует данные в читаемый текст

### Оценка сложности

**Временная сложность построения общей статистики: O(n × m)**
- `n` — количество студентов в группе
- `m` — среднее количество результатов у одного студента
- Для каждого студента функция `mean()` проходит по его результатам (O(m))
- Всего студентов `n`, поэтому суммарная сложность O(n × m)
- Функции `minimum()` и `maximum()` также имеют сложность O(m) каждая
- Поиск лидеров требует дополнительного прохода по всем студентам — O(n)
- Итоговая сложность: O(n × m)

**Пространственная сложность: O(n)**
- Словарь `category_counts` имеет фиксированный размер (5 категорий) — O(1)
- Список `all_means` содержит по одному элементу на студента — O(n)
- Словарь `averages` в `find_top_students()` — O(n)
- Итоговая дополнительная память: O(n)
